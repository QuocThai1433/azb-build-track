AZB Project Hub · FastAPI + SQLAlchemy

Dự án hoạt động như thế nào?

Trang này giải thích mã nguồn cho người mới vào nghề. Hãy đọc tab Bức tranh chung trước, rồi mở lần lượt từng tab tính năng. Mỗi tab tính năng trả lời ba câu hỏi: tính năng này để làm gì, nó chạy ra sao, và nó cho ra kết quả gì. Các thuật ngữ khó đều có giải thích ngay trong tab.

1. Các tầng của ứng dụng

Ứng dụng chia thành nhiều tầng. Mỗi tầng chỉ làm một việc và chỉ nói chuyện với tầng kế bên. Yêu cầu đi từ trái sang phải. Kết quả đi ngược lại từ phải sang trái.

Giải thích nhanh

Request / Response
Request (yêu cầu) là thứ trình duyệt gửi lên: “cho tôi trang /tasks”. Response (phản hồi) là thứ máy chủ trả về, thường là một trang HTML.
ORM
Object-Relational Mapping. Kỹ thuật cho phép bạn làm việc với một dòng trong bảng như làm việc với một đối tượng Python, thay vì viết câu lệnh SQL thủ công.
Tại sao chia tầng?
Khi cần đổi cách lưu dữ liệu, bạn chỉ sửa một tầng. Các tầng còn lại không bị ảnh hưởng. Code cũng dễ đọc và dễ test hơn.

2. Điều gì xảy ra lúc khởi động?

Bạn chạy python app.py. Trước khi nhận yêu cầu đầu tiên, ứng dụng chuẩn bị database.

Giải thích nhanh

Uvicorn
Chương trình “máy chủ” thực sự lắng nghe cổng 5000 và chuyển yêu cầu cho FastAPI. FastAPI chỉ là bộ khung viết logic, tự nó không mở cổng.
Lifespan
Đoạn code chạy một lần khi ứng dụng bật lên (và một lần khi tắt). Nơi thích hợp để chuẩn bị database.
Migration
Một file mô tả “thay đổi cấu trúc database”, ví dụ tạo bảng hoặc thêm cột. Có lịch sử và có số phiên bản, giống như git cho cấu trúc bảng.
Seed
Dữ liệu mẫu nạp sẵn lần đầu để ứng dụng không bị trống.

3. Điều gì xảy ra khi người dùng bấm “Lưu”?

Ví dụ: người dùng sửa tiến độ thực tế của công việc số 12 thành 40 rồi bấm Lưu. Đọc các mũi tên từ trên xuống dưới.

Giải thích nhanh

GET và POST
GET là “cho tôi xem”, không đổi dữ liệu. POST là “tôi gửi dữ liệu lên để lưu hoặc xoá”.
Pydantic
Thư viện kiểm tra và đổi kiểu dữ liệu. Form luôn gửi lên dạng chữ; Pydantic đổi “40” thành số 40 và xử lý trường rỗng.
COMMIT
Lệnh “chốt” thay đổi vào database. Chưa COMMIT thì thay đổi chưa được lưu thật.
Redirect 303
Phản hồi bảo trình duyệt “hãy sang địa chỉ khác bằng GET”. Dùng sau mỗi lần lưu để tránh gửi form hai lần khi người dùng nhấn F5.
Flash message
Thông báo ngắn chỉ hiện một lần ở trang kế tiếp, ví dụ “Đã lưu”. App giữ nó trong cookie giữa hai yêu cầu.

4. Các quy tắc của code

  • Router không viết SQL. Router gọi hàm trong repositories.py.
  • Hàm ghi dữ liệu trong repository tự COMMIT trước khi trả về.
  • Ngày tháng lưu dạng chữ chuẩn ISO, ví dụ 2026-01-15.
  • Tiến độ kế hoạch là phân số từ 0 đến 1. Tiến độ thực tế là số từ 0 đến 100.
  • File database là instance/project_manager.db. Sao chép file này để sao lưu.

5. Bảng thuật ngữ

Route
Một địa chỉ URL mà ứng dụng trả lời, ví dụ /tasks.
Router
Một file Python chứa nhiều route. Mỗi route là một hàm: đọc yêu cầu, gọi logic, trả về trang.
Repository
Nơi duy nhất chứa các truy vấn database. Muốn biết dữ liệu được lấy ra thế nào, chỉ cần đọc file này.
Model
Một class Python tương ứng với một bảng trong database. Mỗi thuộc tính là một cột.
Session
Một “phiên làm việc” với database cho một yêu cầu. Mở khi yêu cầu bắt đầu, đóng khi kết thúc.
Transaction
Một nhóm thao tác được coi là một khối: hoặc tất cả thành công, hoặc tất cả bị huỷ (rollback).
Template
File HTML có chỗ trống. Jinja2 điền dữ liệu vào chỗ trống rồi gửi trang hoàn chỉnh cho trình duyệt.
CRUD
Create, Read, Update, Delete: bốn thao tác cơ bản với dữ liệu (thêm, xem, sửa, xoá).
WBS
Work Breakdown Structure. Mã số của từng đầu việc trong kế hoạch. Khi nhập lại Excel, app dùng mã này để nhận ra “cùng một công việc”.
HSSE
Health, Safety, Security, Environment: sức khoẻ, an toàn, an ninh, môi trường.
